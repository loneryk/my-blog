# 高相关性代码提交 PR

## 继承你的代码

我一般会先明确一个前提：如果有大量同一功能模块下的功能需要开发，我们应该新开不同的分支来更新代码。

但代码分支不应该都以 `main` 分支为基础来开发。这样所有的分支都是平行结构，功能无法相互配合。

为了解决这种问题，每次新增的功能都应在原有代码的基础上变基。例如：

```text
PR 1 feature/branch-1 -> main
PR 2 feature/branch-2 -> feature/branch-1
PR 3 feature/branch-3 -> feature/branch-2
```

这样能保证每条分支都能在保有原来功能的基础上进行新功能的开发。

## 便利审查者审查代码

像上面这样继承代码，能方便审查者查阅代码。审查者只需要关注一个功能的开发，而不是一个模块的代码。如果有问题需要打回，也只会影响一个功能的 PR，提高协作效率。

## 使用堆叠 PR

在 PR 2 的描述中明确注明“Depends on #PR1”，在 PR 3 中注明依赖 PR 2。这样每个 PR 的变更差异（Diff）都是基于前一个 PR 的**增量**，审查者可以清晰地看到每个功能新增了什么，而不会被大量不相关的代码干扰。

如果合并后觉得 commit 过于零散，可以在最终合并 PR 时用 Squash and merge 将 PR 中的所有提交压缩成一个干净的提交，合并到目标分支，让项目历史更加清晰。
